# 베릭스 핸드북 — 원격 동기화판 (v2.17)

클로드 코드가 `state/*.json`만 고쳐도, 브라우저에서 자동으로 최신 상태가 보이는 구조입니다.

```
index.html          핸드북 본체 (렌더링만 담당, 상태는 갖고 있지 않음)
state/
  rev.json          상태 버전 표식 — 이 값이 바뀌어야 브라우저가 새 상태를 채택한다
  core.json         checkpoint / session / arc / place / pc
  party.json        동료
  npcs.json         NPC
  world.json        대륙 지도 (discovered / here / customPlaces)
  dungeon.json      던전
  battle.json       전투 (그리드·토큰·라운드)
  threads.json      진행 중 실마리
  log.json          세션 로그
  feats.json        특성 + 기타 아이템
```

## 배포 (최초 1회)

1. 이 폴더 전체를 GitHub 저장소에 올린다.
2. 저장소 **Settings → Pages**에서 Source를 `main` 브랜치 / `/ (root)`로 지정한다.
3. 몇 분 뒤 `https://<계정>.github.io/<저장소>/` 로 접속하면 핸드북이 열린다.
   이 주소를 폰 홈 화면에 추가해두면 앱처럼 쓸 수 있다.

> `index.html`을 파일로 직접 열면(file://) 브라우저 보안 정책 때문에 `state/` 를 읽지 못한다.
> 이때는 배지에 "로컬 모드"가 뜨고 내장된 40회차 상태로만 동작한다. 반드시 Pages 주소로 열 것.

## 갱신 규칙 (클로드 코드가 지킬 것)

**상태 파일을 고쳤으면 반드시 `state/rev.json`의 `rev` 값을 바꾼다.** 이걸 빠뜨리면
브라우저는 상태가 그대로라고 판단하고 갱신하지 않는다.

```json
{ "rev": "S41-007", "updated": "2026-09-08T11:00:00Z", "note": "1라운드 종료" }
```

`rev`는 `S{회차}-{일련번호}` 형식을 쓴다. 값이 이전과 다르기만 하면 되므로 순서는 상관없다.

갱신 빈도:

| 대상 | 시점 |
|---|---|
| `battle.json`, `core.json`(HP·슬롯·임시HP) | **전투 매 턴 즉시** |
| `core.json`(소지품·골드) | 획득·소모 발생 즉시 |
| `world.json` | 새 지역 이동·발견 시에만 |
| `dungeon.json` | 던전 진입·구역 이동 시 |
| `party.json`, `npcs.json`, `threads.json` | 변화가 생긴 시점 |
| `log.json` | 마을↔던전 등 큰 구역 전환 시 모아서 |

던전·전투가 끝나면 해당 파일을 지우지 말고 빈 상태로 되돌린다
(`battle.tokens: []`, `battle.round: 1`). 파일이 없으면 로딩이 실패한다.

## 브라우저 쪽 동작

- 헤더의 배지가 동기화 상태를 보여준다: `최신` / `갱신됨` / `로컬 모드`
- **자동** 체크박스가 켜져 있으면 20초마다 `rev.json`을 확인해 알아서 반영한다.
  탭을 다시 활성화할 때도 즉시 한 번 확인한다.
- **지금 불러오기** 버튼은 rev가 같아도 원격 상태를 강제로 다시 가져온다.
- `rev`가 이전과 같으면 로컬 저장본(수동 `@@PATCH` 적용 결과)을 유지한다.
  즉 채팅에서 받은 패치를 직접 넣어 쓰던 기존 방식도 그대로 병행 가능하다.

## 알아둘 것

- GitHub Pages는 CDN을 거치므로 커밋 후 반영까지 **수십 초에서 1~2분** 걸릴 수 있다.
  (요청 자체에는 캐시 무효화를 걸어두었지만 Pages 빌드 시간은 어쩔 수 없다.)
- 클라우드 샌드박스의 수정이 `main`에 바로 커밋되는지, 별도 브랜치/PR로 남는지는
  실사용으로 확인이 필요하다. PR로 남는다면 병합해야 화면에 반영된다.
