# CLAUDE.md 개정 기록 (보존용)

이 문서는 평소 읽지 않는다 — 매 턴 컨텍스트에 실리는 CLAUDE.md를 가볍게 하려고 53회차 종료 후(2026-10-23) 옮겼다. 지침을 개정할 때만 맨 아래에 새 항목을 덧붙인다. 각 항목의 "다음 배치 개정 때 재검토"는 이 파일에서 모아 본다.

## 개정 기록 (43회차 직전 ~ 53회차 종료 후)

**43회차 직전 인프라 개정** — 이번에 바뀐 것:
- **문서 구조**: 매 턴 지킬 8줄을 최상단으로 올리고, JSON 스키마 상세는 `archive/state_schema.md`로 분리(필요할 때만 열기). 개정 이력은 맨 아래로 내림.
- **캐릭터 분리**: 한 명 = 파일 하나. `state/chars/_index.json`이 명단의 유일한 출처이며, 동료가 합류해도 `index.html`을 고칠 필요가 없음(기존 `REMOTE_SHEET_IDS` 하드코딩 제거). `party.json`·`npcs.json`·`sheets/`는 사라졌습니다.
- **데이터 일원화**: `feats.json` 삭제(핸드북이 필수로 읽으면서 화면에는 안 쓰던 파일 — 내용이 갈라져 있었음), 성수 봉인 단검 중복 아이템 제거, 40회차 통합 특성 반영, 긴 휴식 후 남아 있던 임시HP·투명화 상태 정리.
- **신설**: 시계(`clocks.json`)·세력(`factions.json`)·의심도(`susp`), 실마리 상태 필드(`st`), 골드 싱크 규칙, 사회 판정에 시계를 거는 규칙.
- **도구**: `tools/validate.js`(커밋 전 검증), `tools/dice.js` 복합식·이점/불리·자연 20 표시·굴림 로그.

**43회차 직전 인프라 개정 (2차)** — 첫 개정 뒤 다시 훑어 찾은 것들:
- **핸드북 경량화**: 대륙 지도가 `index.html` 안에 844KB base64로 박혀 있어 본체의 86%를 차지했다. `assets/map.jpg`로 분리해 984KB → 155KB.
- **도구 추가**: `tools/rest.js`(휴식 일괄 처리 — 동료 자원까지), `tools/seed.js`(로컬 모드용 내장본 갱신), `tools/looks.js`(characters.md 재생성).
- **세션 시작 훅**: `.claude/hooks/session-start.sh`가 세션이 열릴 때 `validate.js`를 자동 실행하고 현재 회차·위치·짧은 휴식 누적을 알려준다.
- **NPC 개성**: 주요 NPC 12명에 `voice`·`drive`·`bond` 반영. 표본이 없는 인물은 "미확정"으로 명시하고 재등장 시 채운다. 검증기가 `voice` 누락을 경고한다.
- **단일 출처 정리**: `characters.md`가 캐릭터 파일의 `look`에서 생성되도록 바꿔 외모 이중 관리를 없앴다. `daria`·`npc_vesperhusk_s36`의 빈 `role`/`trait`을 채우고 `d` 필드를 `trait`으로 통일했다.
- **아카이브 최신화**: `campaign_summary.md`에 제6부(41~42회차)와 세렌 색인, 42회차 훅 2건을 추가했다(40회차까지만 반영돼 있었다).
- **로그 분할**: `log.json` 168항목 → 64항목(38~42회차), 나머지는 `archive/log_archive.json`으로. 80항목을 넘으면 검증기가 알린다.

남은 미확인 항목 — 다음 회차에서 실전 검증 필요:
- `rest.js`·`looks.js`·세션 시작 훅이 실제 진행에서 쓰이는지(도구를 만들어두고 손으로 하던 습관이 남으면 의미가 없음).
- 시계·의심도를 실제 진행 중에 **꾸준히 채우는지**(만들어두고 방치되면 아무 의미가 없음).
- 골드 싱크가 실제 아크 설계에 반영되는지.
- 캐릭터 파일 분리 후 전투 중 갱신이 더 가벼워지는지, 새 동료 합류 절차가 실제로 파일 추가 + 인덱스 한 줄로 끝나는지.
- 사회 판정 시계가 수사·심문 장면을 늘어지게 만들지는 않는지(늘어지면 칸 수를 줄일 것).

**48회차 직전 개정 2차 (사용자 지시, 2026-10-06)** — 브랜치 미동기화·로그 누락 사고의 재발 방지. 두 규칙 모두 지침에는 있었지만 기억에 의존해 빠졌으므로, 도구가 확인하게 바꿨습니다.
- **커밋마다 `main` 푸시**: "회차 종료 시점에만 main 반영"을 "커밋할 때마다 main 반영"으로 바꿨습니다("커밋 · 푸시" 절).
- **세션 시작 훅**: `git fetch` 후 main보다 최근에 커밋됐는데 main에 없는 커밋이 있는 원격 브랜치, 그리고 현재 브랜치가 main보다 뒤처진 경우를 경고합니다. 얕은 복제본(클라우드 세션 기본값)이면 먼저 전체 이력을 받아 커밋 수를 바르게 셉니다 — 처음엔 이 처리가 없어 9월 중순의 옛 브랜치 셋(`claude/game-quality-improvements-*`, `claude/session-43-*`, `claude/session-44-*`)이 100여 커밋 앞선 것처럼 보였으나, 전체 이력으로 대조하니 셋 다 main에 전부 포함돼 있었습니다(브랜치에만 있는 커밋 0개).
- **`validate.js` 로그 검사**: 현재 회차의 `log.json` 항목이 0건이거나, 최근 5회차 중 체크포인트 폴더가 있는데 로그(`log.json`+`archive/log_archive.json`)가 0건인 회차를 경고합니다. 회차를 개시할 때 "개시" 항목을 로그에 남기면 경고가 사라집니다.
- **"현재 진행 상황" 절**: 수치를 지우고 원본 파일을 가리키는 안내로 바꿨습니다.
